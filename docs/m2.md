# M2 reference

M2 adds two transports over the same application operations: MCP over stdio and
the existing CLI. Neither transport owns business logic. Both construct the
same typed request values and call `Application`, which opens the shared SQLite
store and returns the same JSON value.

## MCP

Run the server with:

```sh
prose mcp
```

The stdio server exposes typed tools for `pack`, `context`, `verb`, `surface`,
`draft`, `attestation`, `capture`, and `render`. Domain tools use an `action`
field where the CLI has subcommands. Together they expose the same pack CRUD,
selection, import/export, context and verb serving, surface resolution, draft
chains, and attestation operations as the CLI. MCP transport envelopes differ,
but the tool's text content is the exact compact JSON value returned by the
shared application operation.

The MCP server is still a broker, not a brain. It serves instructions and
records versions and reported human approval; it does not execute a verb or
infer approval.

MCP client callbacks may eventually support attached-agent editing flows.
Sampling itself is deprecated in the MCP 2025-11-25 specification and rmcp 2.2,
so M2 does not couple prose's future broker transport to that deprecated API.

## Host pointer

```sh
prose render --host opencode
```

The rendered adapter is intentionally small. It tells the host to fetch live
context and verb material, record draft versions, ask the human to approve the
exact final version, and only then record an attestation. It never copies a
voice guide into static host configuration, so pack edits cannot drift from a
rendered copy.
