# M4 operational and audit hardening

## Native pack-item provenance

Schema v3 links every newly installed context, verb, tier, and surface-mapping
revision to an immutable item origin. Unchanged items carried into a later pack
snapshot retain the same origin; changed items receive a new one. CLI and MCP
can inspect the origin of any item at its latest or an exact pack revision, and
served contexts, verbs, and surface resolutions include their constituent
origins.

An `approved-draft` origin names one exact draft version and the exact approved
attestation row for that version. Draft authorship is not the gate: a human may
approve an agent-authored version. prose verifies the human approval and derives
context content or verb instructions directly from the stored draft inside the
same write transaction. A caller cannot pair unrelated text with that approval.

An `external-import` origin requires no user annotation. prose automatically
records a SHA-256 digest over canonical typed item material, the ingestion
channel, and its timestamp. A source label and URI are accepted when naturally
available but remain optional so provenance does not make importing material
expensive enough to bypass.

Origin and revision-link tables are append-only. Migration never invents an
approved relation from content equality.

## Capture observations

Capture events distinguish two immutable observations:

- `submit-attempt` records content observed when submission was attempted. It
  has no parent and is not evidence that the remote surface accepted a post.
- `surface-confirmed-post` records the exact content observed only after the
  surface confirms the post. It references an existing `submit-attempt` by its
  stable capture ID. prose never infers this observation.

A confirmed post must have the same surface and normalized URL as its parent.
URL matching parses absolute URLs and ignores query strings and fragments; the
original event URL remains stored unchanged. Content is not normalized, so the
confirmed event preserves exactly what its caller observed and may differ from
the attempted content.

Caller-provided IDs are stable idempotency keys. Retrying the same ID succeeds
only when every observation field, including observation type and parent, is
identical. Capture recording remains available without an attached backend.

Schema v3 adds the observation and parent fields transactionally. Captures
migrated from schema v2 become `submit-attempt` events without parents; no
confirmation is inferred.

## Service hardening

M4 narrows browser HTTP to health, verb enumeration, surface resolution,
capture recording, and assist. Administrative and agent-harness operations stay
on CLI/MCP rather than the browser router. Both IPv4 and IPv6 binds must be
loopback, no CORS origins are granted, health actively checks the store, and
SIGINT/SIGTERM use graceful draining.

The command backend has a text-only, direct-executable contract with one
deadline and 256 KiB limits for each output stream. Timeout and cancellation
terminate the immediate process and its Unix process group. Health retains only
the bounded last outcome, category, and timestamp; backend output and request
material are never diagnostics.

## Browser reliability and packaging

The M4 extension uses host adapters rather than global button-label matching.
GitHub is supported only on `/<owner>/<repository>/pull/<number>` routes and
only when one recognized PR textarea belongs to the submitted form. Linear's
SPA fallback requires explicit composer, Lexical editor, and submit-control DOM
markers; form-associated controls are left to the native submit event. These
selectors describe host mechanisms and DOM roles, not pack mappings, voice,
approval tiers, or content judgment. Unsupported and ambiguous pages are inert.

Each capture is an exact, untrimmed editor snapshot. Trimming is used only to
reject empty snapshots. Assist state is scoped to the editor and candidate: a
draft reference is included only while the editor's complete captured value is
byte-for-byte equal to the inserted candidate. Any human input permanently
invalidates that association, even if the text is later restored. Editor removal and
SPA navigation invalidate that association. Native form submits and known SPA
clicks produce only stable-ID `submit-attempt` observations, including attempts
later prevented by the host. The extension currently emits no
`surface-confirmed-post` observations: neither host exposes a sufficiently
stable, exact-content acceptance marker in the adapter. This deliberately
avoids turning failed, prevented, or merely clicked submissions into evidence
of a post.

Attempts are persisted before network delivery. Network failures, 429s, and
5xx responses retain the event and its ID for alarm/startup retries. Other 4xx
responses move a bounded diagnostic containing only ID, status, and timestamp
to dead-letter storage, then allow later events to proceed. Queue operations
are serialized so concurrent messages and alarms cannot overwrite recovery
state.

Chrome and Firefox are separate generated MV3 packages. Their manifests are
generated from browser-specific templates, with the version read from
`Cargo.toml`; templates intentionally contain no version to drift. Firefox
uses MV3 background scripts while Chrome uses a service worker. See
`extension/README.md` for build, temporary-install, and signing handoff steps.
