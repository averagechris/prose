# M3 reference

M3 adds a loopback HTTP transport, a command-based attached-agent spike, and an
unpacked Chrome/Firefox extension for GitHub and Linear. The HTTP routes call
the same `Application` operations used by CLI and MCP.

## Local service

```sh
prose serve
prose serve --agent-command /path/to/prose-agent-wrapper --agent-arg value
```

The default address is `127.0.0.1:37673`. v1 refuses non-loopback IPv4 and IPv6
bind addresses. The M4 service does not emit CORS grants: extension background
pages use explicit host permissions, while web origins and wildcard extension
origins receive no access-control response headers. There is no remote serving
or remote authentication; loopback remains the network boundary.

Browser HTTP is deliberately narrower than CLI and MCP. Routes under `/v1`
expose health, verb enumeration, surface resolution, capture recording, and
assist only. They do not expose pack mutation/import, raw contexts, arbitrary
draft operations, attestation recording, or render. Every exposed handler uses
the shared application layer; CLI and MCP retain their broader operation sets.

## Attached-agent spike

Assist is unavailable unless `--agent-command` or `PROSE_AGENT_COMMAND` is
configured. The configured executable receives deterministic assembled
material on stdin and must write only candidate text to stdout. Repeated
`--agent-arg` values are passed before stdin. The default timeout is 60 seconds
and can be changed with `--agent-timeout-seconds`. prose does not select a model,
judge output, or infer approval.

The timeout is one deadline across stdin delivery, output collection, process
completion, and termination. stdout and stderr are each capped at 256 KiB.
Commands are executed directly without shell interpolation. On Unix, each
backend invocation has its own process group so timeout or cancellation kills
descendants and reaps the immediate child. Successful stdout is preserved
exactly except for removal of one terminal LF or CRLF; stderr is never copied
into client errors or health diagnostics.

The configured backend is a trust boundary. Run it as a text-only agent with
filesystem, shell, network, and posting tools disabled unless the operator
explicitly wants those capabilities. prose can constrain its own assembly and
recording, but it cannot override permissions inside an external agent runtime.

The assembly contains the exact context module, verb instructions, selection,
and surrounding context. The source selection is recorded as a capture-authored
draft version before backend invocation; a successful candidate is appended as
an agent-authored version. If the backend is absent or fails, assist returns
`503 backend_unavailable` while capture endpoints remain available.

When assist receives an existing draft target, that exact version is validated
as the parent of a newly appended capture-authored source-selection version.
Only then is the backend invoked, and a candidate becomes an agent-authored
child of that source version. Thus backend absence or failure still leaves the
supplied source selection recorded.

`GET /v1/health` opens and queries the store on every check. It separately
reports service readiness, store readiness/category, overall readiness, whether
a backend is configured, and the last backend outcome/category/time. The last
diagnostic uses bounded categories only and never includes command output,
prompt material, paths, or stderr. Store unavailability returns HTTP 503; a
missing backend does not make capture/store readiness fail.

The command transport wins the M3 spike because it is backend-neutral and has a
small explicit contract. OpenCode can be attached through a wrapper that reads
stdin and invokes `opencode run`; ACP or a future host-mediated inference
extension can replace this adapter without changing storage, assembly, HTTP, or
extension code.

## Submit-time captures

Schema v2 adds immutable `capture_events`. M3 captures are submit-attempt
observations: they record surface, URL, submitted content, optional exact draft
version, metadata, and prose's timestamp. Capture is append-only and does not
depend on the attached backend. Schema v3 retains these as `submit-attempt`
events; it does not infer that any old event was confirmed by the surface.

The extension observes GitHub and Linear submit actions and reports the editor
content available at that moment. This is submit-time evidence, not a claim that
the remote surface accepted the request; metadata identifies the browser event.

## Extension

Load `extension/` as an unpacked Chrome extension or temporary Firefox add-on.
`nix build .#prose-extension` also produces `unpacked/` and
`prose-extension.zip` artifacts for manual installation and signing workflows.
It:

1. Enumerates the active pack's verbs into a selection context menu.
2. Detects `github-pr` or `linear` as a surface ID.
3. Asks prose to resolve that surface through user-owned pack mappings.
4. Sends selected and surrounding text to `/v1/assist`.
5. Replaces the selection with the returned candidate.
6. Captures editor text on submit independently of assist availability.

Capture events queue in extension-local storage if the service is unavailable
and retry on browser startup and the periodic verb refresh. Stored URLs omit
query strings and fragments.

The extension contains no context mapping, voice guidance, verb instructions,
tier definition, or model call. Users must provide surface mappings in their
active pack.
